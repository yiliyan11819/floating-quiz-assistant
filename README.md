## 它能干什么

| | |
|---|---|
| 🪟 **常驻置顶浮窗** | 无边框圆角小窗，钉在所有窗口最上层。全屏播网课也压不住它，可拖动、可缩放、可折叠成屏幕边缘的小胶囊 |
| ⚡ **三种识别模式** | 自动持续读屏 / 手动按一下答一次 / 热键框选任意区域 |
| 🌊 **流式作答** | 调用 DeepSeek 多模态模型，答案逐字出现，不是等半天才弹一整块 |
| 🧮 **公式正常渲染** | Markdown + KaTeX，`$x^2$`、`$$\int$$` 都能正常显示，不是一堆乱码 |
| 💬 **随时追问** | 浮窗底部对话框直接问「为什么选 B」「换个方法讲」，模型带着原题上下文回答 |
| ♻️ **同题去重缓存** | 同一道题第二次出现，秒出缓存答案并标注「已答过」，不再花钱 |
| 📓 **错题本** | 追问过的题自动入库，可搜索、可导出 Markdown |
| 🔐 **Key 只存本机** | 用 Windows 系统级加密（DPAPI）保护，不上传、不写日志 |

## 给同学的用法（下载即用）

1. 到本仓库的 **[Releases](../../releases)** 页面下载 `FloatQuizHelper-x.x.x-portable.exe`
2. **双击就能跑**，不用安装、不写注册表、不弹 UAC
3. 首次启动会自动打开设置页，把 API Key 填进去（[怎么拿 Key](#api-key-从哪来)），点「测试连接」确认通了
4. 关闭设置页，浮窗就绪

> **Windows 提示「已保护你的电脑」怎么办？**
> 这是 SmartScreen 对没有代码签名证书的小众软件的默认拦截，不是病毒。
> 点 **更多信息 → 仍要运行** 即可。

**开机要用时找不到浮窗？** 它在系统托盘里（右下角小三角）。左键点托盘图标显示/隐藏，右键出菜单。

## 三种识别模式怎么用

浮窗顶部三个按钮互斥切换：

### 手动模式（按一次答一次）

点「**识别本页**」→ 截取监控区域（没设过就是整屏）→ 识别 → 作答。
不想开自动、只想偶尔用一下的时候最省心。

### 自动模式（持续读屏）

1. 切到「自动」→ 第一次会弹出全屏遮罩，**拖拽框选要监控的区域**（比如刷题网页的题目卡片那一块），坐标会记住
2. 之后它每 500ms 截一次这个区域，算感知哈希比对：
   - 画面**连续静止 1 秒**且没答过 → 触发识别
   - 识别过程中画面变了 → 立刻中断当前请求，重新计时
3. 浮窗底部会实时显示 `静止 0.8s · 已触发 3 次`，随时可以「暂停 / 恢复」

框选范围**越小越好** —— 只框住题目本身，速度更快、token 更少。

### 自由截图模式

按热键 `Ctrl + Shift + A`（可改），或者点模式里的「截图」→ 全屏遮罩 → 拖拽框选 → 松手后**只识别你框的那一块**。全程不用碰浮窗。

## 会花多少钱

用的是 DeepSeek 官方 API 按量计费，一张截图大约折算 **≤ 1024 输入 token**（跟分辨率相关，所以裁剪真的很省）。

粗算一笔账（以 DeepSeek 2026-09 公示价为例，实际以官网为准）：

| 场景 | 单次大致消耗 | 说明 |
|---|---|---|
| 一道题识别 | ~1000 输入 token + 几百输出 token | 输入便宜、输出稍贵 |
| 追问一次 | 输入带上下文，但**命中缓存的部分按缓存价计费**（约为未命中的 1/50） | 所以多轮追问不心疼 |
| 同一题再来一遍 | **0** | 直接读本地缓存，根本不发请求 |

日常每天刷几十道题，一般也就是几毛钱到一两块的水平。**想更省**：把监控区域框小、答案风格切「只要提示」（输出更短）。

## 自动模式为什么不会烧钱

这是很多人的第一反应：「一直读屏不会把额度刷爆吗？」

不会。看它的判定条件：

```
每 500ms 截一帧
  ├─ 画面和上一帧不一样  → 重置「静止计时」，什么都不做
  └─ 画面和上一帧一样 且 已经静止满 1 秒 且 这题没答过 → 才触发识别
```

**视频播放的时候，画面每一帧都在变** —— 永远满足不了「连续静止 1 秒」，所以永远不触发。这不是 bug，是设计。

只有真正「停住的题目」才会被识别：翻到一道题不动了、点开一道题的解析页停住、PDF 停在一页上。

再叠三层保险：

1. **同题去重**：每题算一个 64 位感知哈希，哈希距离 ≤ 4 就认为是同一题，直接出缓存
2. **已处理标记**：一帧只要被处理过（哪怕回复是「未检测到题目」），在画面再次变化前都不会重复触发
3. **失败冷却**：识别失败后，同一画面 30 秒内不再重试

## 从源码构建

需要 **Node.js 20+** 和 **Windows**。

```bash
git clone https://github.com/<你的用户名>/float-quiz-helper.git
cd float-quiz-helper
npm install
```

脚本一览：

| 命令 | 作用 |
|---|---|
| `npm start` | 构建并启动（开发调试） |
| `npm run build` | 只构建到 `dist/`（生成图标 + esbuild 打包） |
| `npm run dist` | 构建 + 打包成免安装单文件 exe，产物在 `release/` |
| `npm run typecheck` | 跑一遍 TypeScript 类型检查 |

> **国内网络**：仓库里的 `.npmrc` 已经把 npm 源和 Electron 二进制镜像指到了 npmmirror，
> 直接 `npm install` 就行，不用挂代理。

## 实现要点

如果你是想看代码而不是用软件，这几处可能有点意思：

| 位置 | 干了什么 |
|---|---|
| `src/main/capture.ts` | **DPI 正确性**。渲染层的框选坐标是 DIP 逻辑像素，`desktopCapturer` 给的是物理像素。这里用「实测比例」（拿到的图宽 ÷ 显示器 DIP 宽）换算，而不是直接乘 `display.scaleFactor`，所以 125% / 150% / 混合 DPI 多屏都不会偏移 |
| `src/main/dhash.ts` | 9×8 灰度 + 逐行相邻比较 → 64 bit 感知哈希。顺带做全黑帧检测（全屏独占游戏会让截图变全黑） |
| `src/main/monitor.ts` | 自动模式状态机。相对原始设计补了一个 `lastHandledHash`：否则「图里没有题目」这种不入缓存的结果会导致同一张静态画面被无限重复识别 |
| `src/main/deepseek.ts` | SSE 流式解析 + 指数退避重试。超时用的是**空闲超时**（首字节 30s，之后每收到一段重置 60s）而不是整体 60s 硬切，长解答不会被腰斩 |
| `src/main/store.ts` | API Key 用 `safeStorage`（Windows 下是 DPAPI）加密后落盘；JSON 原子写（temp + rename），断电不会留半截文件 |
| `src/renderer/markdown.ts` | 先把代码块和公式抠成占位符 → 交给 marked → 再换回 KaTeX 渲染结果 → 过 DOMPurify。这样公式里的 `_` `*` `\` 不会被 Markdown 语法误伤；另外加了启发式判断，避免把「售价 $5 和 $10」当成行内公式 |
| `scripts/make-icon.js` | 纯手写 PNG / ICO 编码器（zlib + 4× 超采样抗锯齿），不依赖任何图形库和二进制依赖 |

目录结构：

```
float-quiz-helper/
├─ src/
│  ├─ main/            # 主进程
│  │  ├─ main.ts       # 应用生命周期、IPC、识别与追问编排
│  │  ├─ windows.ts    # 浮窗 / 框选遮罩 / 设置页 / 错题本 / 托盘
│  │  ├─ monitor.ts    # 自动模式状态机
│  │  ├─ capture.ts    # 截屏与 DPI 换算
│  │  ├─ dhash.ts      # 感知哈希
│  │  ├─ deepseek.ts   # API 客户端（SSE 流式）
│  │  ├─ store.ts      # 本地持久化
│  │  └─ preload.ts    # contextBridge 白名单
│  ├─ renderer/        # 渲染层（无框架，原生 TS）
│  │  ├─ float.*       # 浮窗
│  │  ├─ overlay.*     # 框选遮罩
│  │  ├─ settings.*    # 设置页
│  │  ├─ notebook.*    # 错题本
│  │  └─ markdown.ts   # Markdown + KaTeX 渲染
│  └─ shared/          # 共享类型与 Prompt 模板
├─ scripts/            # 构建与图标生成
└─ electron-builder.yml
```

技术栈：**Electron 33 + TypeScript**，构建用 esbuild（不引 webpack/vite，让「clone → npm i → npm run dist」这条路最少坑），界面手写原生 TS + CSS，没有前端框架。

## 常见问题

**Q：报 401 / 提示 Key 无效？**
Key 复制错了或者已失效。设置页点「测试连接」会直接告诉你原因，换一个 Key 再试（设置里填新的会覆盖旧的）。

**Q：报 402 / 余额不足？**
DeepSeek 账户没钱了，去官网充值。

**Q：识别出来是「未检测到题目」？**
框选区域里确实没有题目，或者截图太糊。把监控区域重新框一下、只框题目本身。

**Q：自动模式一直不触发？**
1. 确认浮窗底部显示的是 `静止 x.xs`（说明在采样）
2. 可能是框选区域里画面一直在动（比如有视频/动画），触发不了静止条件
3. 也可能是这题已经答过了 —— 命中「已处理」标记，属于正常行为
4. 试试把「静止阈值」调小（设置页），或者直接用「识别本页」

**Q：浮窗全黑 / 花屏？**
极少数老显卡驱动、远程桌面、虚拟机会让硬件加速崩掉。设一个环境变量再启动就能走软件渲染：

```bash
set FLOATQUIZ_DISABLE_GPU=1
```

**Q：热键没反应？**
`Ctrl+Shift+A` 可能被别的软件占了（QQ、截图工具都爱抢）。设置页里换一个。

**Q：数据存在哪？**
`%APPDATA%\float-quiz-helper\`（设置、缓存、错题本三个 JSON）。设置页底部能直接打开这个目录。

## 已知限制

- **只做了 Windows**。核心逻辑是跨平台的，但窗口行为、DPI、托盘细节都按 Windows 调的
- 全屏**独占**应用（部分游戏、部分播放器）会让截图变黑，此时自动模式会跳过该帧
- 「图片输入」依赖 `deepseek-flash` 这个模型；换成纯文本模型会报错
- 界面只有中文
